# network-monitor

Веб-приложение на PHP для просмотра syslog сетевых устройств и оперативного
управления частью настроек коммутаторов. Приложение рассчитано на Apache2.

## Модули

### Меню и управление устройствами

- `html/network_devices/main.php` — меню с переходами к управлению устройствами
  и просмотру журналов.
- `html/network_devices/devicelist.php` — получает перечень типов и устройств
  из MySQL (`dev_type`, `devices`), проверяет доступность через `fping`,
  позволяет добавлять/редактировать устройства и менять флаг `blocked`.
  Для Cisco переименование вызывает Expect-сценарий; обновление инвентарных
  списков выполняется запросами к HTTP API.
- `html/network_devices/portlist.php` — отображает интерфейсы, статусы и PoE,
  получает часть данных через `html/LogReadGetPortInfo.php` и вызывает Expect
  для изменения настроек Cisco.
- `html/network_devices/mikrot_port_renamer.php` — читает данные интерфейсов
  MikroTik по SNMP и выводит команды транслитерации имен портов; сам по себе
  конфигурацию устройства не применяет.
- `html/network_devices/DevJSonList.php` — выдает список устройств из БД в JSON.
- `html/LogReadDevInventorySQL.php` — получает этот JSON, опрашивает устройства
  по SNMP и обновляет файлы `html/LogRead/LogRead.<vendor>.list`.
  `html/LogReadDevInventory.php` — отдельная старая версия обновления
  списков коммутаторов непосредственно из файлов.

### Структура базы данных

SQL-запросы приложения используют две таблицы: `dev_type` (справочник типов)
и `devices` (устройства с внешним ключом `type_id`). Ниже приведена схема,
созданная по полям, читаемым и изменяемым PHP-кодом:

```text
┌────────────────────┐       1 ──────── N       ┌─────────────────────────────┐
│ dev_type           │                           │ devices                     │
├────────────────────┤                           ├─────────────────────────────┤
│ PK id              │◄──────────────────────────│ FK type_id                  │
│ UQ devtype         │                           │ PK id                       │
└────────────────────┘                           │ UQ ip_address               │
                                                 │    devname                  │
                                                 │    blocked                  │
                                                 │    comment                  │
                                                 └─────────────────────────────┘
```

Полный скрипт создания схемы: `setup/create_database.sql`. Он создает базу
`switches`, обе таблицы, индексы и связь типов с устройствами.

Значение `blocked` используется для управления резервным копированием текстовой
конфигурации коммутаторов в систему контроля версий на сервере gitlab.
Система регулярного копирования конфигураций сетевого оборудования размещена в 
другом репозитории: switch-config-backuper


### Просмотр журналов в реальном времени

`html/LogRead.php` выбирает файл по параметру `site` (`site1`, `msk` или
`site2` по умолчанию), читает последние строки через `tail`/`grep`, исключает
часть сообщений, сопоставляет IP с инвентарными списками и форматирует записи.
Параметры `n`, `t` и `tr` управляют количеством строк, автообновлением и
преобразованием текста. Списки поддерживаемых устройств находятся в
`html/LogRead/`.

`etc/rsyslog.d/50-default.conf` направляет сообщения устройств в
`/var/log/R/...`. В `html/` предусмотрены ссылки:

- `LUBDev.log` → `/var/log/R/88.147.189.196/syslog`
- `MSKDev.log` → `/var/log/R/MSK/syslog`
- `PMPDev.log` → `/var/log/R/185.93.41.47/syslog`

Ссылки хранят только пути назначения: сами логи не входят в репозиторий.
Для работы веб-сервера целевые файлы должны существовать, а пользователь
Apache должен иметь к ним право чтения.

### Взаимодействие с отдельной системой бэкапов

Интеграция с системой резервного копирования конфигураций производится через
флаг `blocked`, инвентарный JSON endpoint и вызовы HTTP API этого приложения.
Фактический контракт с внешней системой, авторизация API и обработка ошибок
описаны отдельно в репозитории системы бэкапов switch-config-backuper

## Состояние и ограничения

В репозитории отсутствуют конфигурация Apache, схема/начальные данные MySQL
и сама конфигурация среды установки. Приложение загружает параметры из
`/etc/network-monitor/network-monitor.cfg`; образец с примерами заполнения
значений конфигурационного файла находится в `config/network-monitor.cfg.example`.

Для установки конфигурации вне DocumentRoot:

```sh
sudo install -d -o root -g www-data -m 0750 /etc/network-monitor
sudo install -o root -g www-data -m 0640 \
  config/network-monitor.cfg.example /etc/network-monitor/network-monitor.cfg
sudoedit /etc/network-monitor/network-monitor.cfg
```

Замените все `EXAMPLE_*` на значения вашей среды. Файл использует формат
`ИМЯ=ЗНАЧЕНИЕ`: одна запись на строку, без кавычек; комментарии начинаются с
`#`. Не помещайте в значения перевод строки. PHP и Expect читают этот же файл.
Пользователи Apache и CLI-задачи, запускающие инвентаризацию, должны иметь доступ 
на чтение; у файла не должно быть прав для остальных пользователей.


Среди PHP-зависимостей по коду используются `mysqli`, `snmp`, `mbstring`;
также нужны `fping`, `expect`, `telnet`, `tail` и `grep`. Установка должна
разрешать PHP запускать необходимые команды. Для rsyslog необходимы правила
создания каталогов и файлов с правами, подходящими для чтения Apache.
